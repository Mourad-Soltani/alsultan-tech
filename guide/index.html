البدء السريع (30 ثانية)

  1. افتح /app/ عبر https:// أو http://localhost (ليس file:// إذا أردت النشر المباشر).
  2. اضغط F12 ← Console ← يجب أن ترى: 
    SELF-TEST: 14/14 passed
  3. عدّل الاسم والواتساب والألوان ثم اضغط معاينة 👁 لترى التطبيق داخل iframe.
  4. حمّل حزمة PWA أو Store — جاهزة للسحب إلى Netlify Drop.
كل شيء يعمل محليًا في المتصفح. لا خادم، ولا بيانات تُحفظ خارجيًا.

النشر المباشر إلى Netlify

  • التوكن: يبدأ بـ nfp_ من User settings ← Applications ← Personal access tokens. لا يُحفظ، ويُرسل فقط إلى api.netlify.com. زر «فحص» يستدعي GET /sites.
  • اسم الموقع (اختياري): أحرف صغيرة وأرقام وشرطات فقط.
  • Site ID: يُملأ بعد أول نشر، والنشر التالي يحدّث الموقع نفسه.

المسار

  1. تحميل JSZip (cdnjs ثم unpkg ثم jsdelivr)
  2. توليد PWA
  3. POST /sites إن لم يوجد Site ID
  4. POST /sites/{id}/deploys مع ZIP
  5. استعلام كل 1.5ث حتى state=ready (40 محاولة)
  6. عرض الرابط وتحديث حقل Host تلقائيًا
عبر file:// يفشل الاتصال بـ Netlify بسبب CORS. افتح عبر https أو npx serve .

الأمان والاختبارات

runSelfTest() يشغّل 14 اختبارًا بعد 800ms من load: readConfig، normalizeSha، parseServices، parseStats، buildManifest، buildAssetLinks، escapeHTML، jsonForScript، buildSW، generateAppHTML، جدول القوالب، سلامة DOM ids.

الإصلاح الحرج

كل إغلاق script داخل JS يُكتب بشرطة مائلة مسبوقة بشرطة عكسية. في JS تساوي \/ نفس / وقت التشغيل، لكن محلل HTML لا يرى الوسم الخام فلا ينتهي البلوك مبكرًا.

// خطأ: يكسر الصفحة
s.push('</script>');
// صحيح
s.push('<\/script>');

استكشاف الأعطال

التوكن غير صالح (401)

أنشئ توكنًا جديدًا وانسخه كاملًا.

اسم الموقع محجوز (409/422)

جرّب اسمًا آخر.

الموقع غير منشور

انشر مجلد www/ أولًا وتأكد أن /manifest.json يفتح.

شريط العنوان يظهر داخل التطبيق

بصمة assetlinks.json لا تطابق مفتاح التوقيع.

فشل تحميل JSZip

تحقق من الإنترنت؛ تُجرَّب 3 شبكات CDN.

الأيقونات لا تظهر بعد النشر

تأكد من رفع مجلد icons/.

نصائح احترافية

  • ارفع شعارًا PNG شفافًا للحصول على أيقونات maskable نظيفة.
  • اختر Package ID فريدًا من البداية؛ لا يمكن تغييره بعد النشر.
  • انسخ android.keystore وكلمة المرور خارج المشروع وخارج Git؛ فقدانهما يعني تطبيقًا جديدًا.
  • بعد أي تعديل أعد توليد الحزمة؛ الكاش الجديد يضمن وصول التحديث حتى دون إنترنت.

Quick Start (30 seconds)

  1. Open /app/ via https:// or http://localhost (not file:// for direct deploy).
  2. Press F12 → Console and look for: 
    SELF-TEST: 14/14 passed
  3. Edit name, WhatsApp and colors, then click Preview 👁.
  4. Download the PWA or Store bundle — ready for Netlify Drop.
Everything runs locally in the browser. No server, no external data storage.

Direct Deploy to Netlify

  • Token: starts with nfp_; never stored; sent only to api.netlify.com. “Check” calls GET /sites.
  • Site name (optional): lowercase letters, digits, dashes.
  • Site ID: filled after the first deploy; later deploys update the same site.
  1. Load JSZip (cdnjs → unpkg → jsdelivr)
  2. Generate PWA
  3. POST /sites if no Site ID
  4. POST /sites/{id}/deploys with ZIP
  5. Poll every 1.5s until state=ready (40 tries)
  6. Show URL and update Host
Over file:// the Netlify call fails (CORS). Use https or npx serve .

Security & Tests

runSelfTest() runs 14 tests 800ms after load: readConfig, normalizeSha, parseServices, parseStats, buildManifest, buildAssetLinks, escapeHTML, jsonForScript, buildSW, generateAppHTML, template table, DOM id integrity.

Critical fix

Every script-closing tag inside JS is written with an escaped slash. In JS \/ equals / at runtime, but the HTML parser never sees a raw closing tag, so the script block survives.

Troubleshooting

Token invalid (401)

Create a new token and copy it fully.

Site name taken (409/422)

Try another name.

Site not published

Deploy www/ first; make sure /manifest.json opens.

Address bar inside the app

The assetlinks.json fingerprint does not match the signing key.

JSZip load failed

Check your connection; 3 CDNs are tried.

Icons missing after deploy

Make sure the icons/ folder was uploaded.

Pro Tips

  • Upload a transparent PNG logo for clean maskable icons.
  • Pick a unique Package ID from day one; it cannot change after publishing.
  • Back up android.keystore and its password outside the project and Git; losing them means a new app.
  • Regenerate the bundle after any edit; the new cache stamp ships the update even offline.
